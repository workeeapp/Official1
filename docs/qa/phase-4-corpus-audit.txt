================================================================================
COVERAGE GAPS
================================================================================

Verified gaps in corpus/DSL:
- No multi-turn (corpus.ts / run-case.ts).
- No list_ops (delete_list / alter_list) — conflicts with current whole-list product path.
- No item_id / filing_id / reminder_id / contact_id assertions.
- No messages, handoff, show_dump, show_icon, attachments, linked_lists,
  recurrence/occurrence_*, guest mode.
- WORKER_SAVED_DATA always empty — inventory / «מה יש לך» not covered.
- Conversational quality barely scored (needles + looksLikeAsk only).

False-pass risks (verified mechanics):
- Soft any / hold_or_confirm_or_ask + weak looksLikeAsk.
- lists_has_action count without identity.
- Response-only cases (shared-list-found-no-not-found).
- Soft suite threshold 0.7 ⇒ up to ~7/24 failures still “green”.

False-fail risks:
- list-not-filing vs delete_list.
- hold_present if hold deprecated in schema/runtime.
- reminder-stop-nudge-keep-item without prior turn.
- Product DELETE CONFIRM (empty mutate + ask) failing cases that require immediate remove.

Does 0.7 measure quality?
  Fact: it measures “≥70% of constraint bags passed,” not calibrated difficulty,
  not conversational quality, not engine correctness.
  Recommendation: treat as smoke/regression gate only; use a stricter core subset
  (e.g. 100% on 12–15 cases) for prompt A/B.

PRIORITIZED MODEL-ONLY EVALUATION SET (PROPOSAL)
================================================================================

Tier A — operational ACTION/schema (must-pass; raise gate to ~1.0 on this subset)
  1. Filing vs lists routing (keep remove/update; tighten names).
  2. Shopping done → remove (add item/item_id when setup provides ids).
  3. Ambiguous list name → ask, lists=[].
  4. Meeting ≠ shopping.
  5. Directory add/remove with confirm-aware constraints
     (empty remove + ask OR remove+id after כן — multi-turn).
  6. NEW: whole-list delete → list_ops.delete_list (replace/augment list-not-filing).
  7. Safety: delete-everything (keep).
  8. No invented clock (keep; tighten).
  9. Filtered multi-delete with title needles or ids.
 10. Clear personal shopping without touching shared
     (assert no remove of shared item text).

Tier B — conversational quality (new constraint types recommended)
  - Clarification: ask when missing time/list; forbid inventing fields.
  - Naturalness: forbid schema jargon in response (extend response_forbids_any).
  - Avoid unnecessary questions when facts are complete.
  - Context: use prior assistant ask in multi-turn.
  - Proactivity/topic emoji: optional, low weight (show_icon) — not blocking.
